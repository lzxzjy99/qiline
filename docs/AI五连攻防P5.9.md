# 已有五连的攻防 · P5.9 / v0.5.9

本轮修复形成五连后忽略提子拆线、原线救棋以及必败时走无关棋的问题。AI 的简单、标准、困难三档共同使用新判断；困难预算仍为 8 秒、200,000 次试算、最多 12 条显式命令。

## 复现

`tests/ai-claim-defense.test.mjs` 使用完整合法记录构造局面，不注入棋盘。19 路固定五子、延迟 4 手、关闭三手换色：

```
A1 C2 B2 D3 C3 E4 D4 F5 K1 C1 L2 S3 M3 S5 N4 S7 E5 B1
```

黑 A1–E5 在第 17 手成五、21 手到期；白 B1–F5 在第 18 手成五、22 手到期。黑应 A2 救住原五连。旧版 1 层搜索补 O5、2 层搜索走 E3；白 A2 提 A1 后，黑原五连取消，后成的五连比白更晚到期。新版浅层也选 A2，核心重放验证原五连在第 21 手获胜。反色并交换 A/B 后同样验证。

在同色换线继承下，补 O5 可以合法继承第 17 手的时钟，即使 A1 被提仍能先确认。该规则下保留换线选择，避免把有效换线误改成强制救原线。

另一个回归局面是 A1–E5 新成五、A1 有两气，攻击方无法强制拆线。旧版搜索证明必败后会选无关的 F5/F6；新版在同为必败的着法中仍优先收紧 A1 的气。此项验证的是有效抵抗，不是声称该局存在获救手段。

## 修复

- 跟踪实际存在的五连及组成棋块。同色换线继承枚举现存完整线；提掉无关棋块不再误标为拆五。
- 保留确认期限内可能受攻击棋块的气点，最多关注六气；加入周围紧气棋块的反提、连接救棋点。所有候选继续经过原内核检查，PSK、自杀禁手和时钟均由内核判定。
- 一气五连按下一手由谁走分别评分；二、三、四气逐级评价。按每色最有价值的确认机会评分，防止多个重叠五连简单叠分，掩盖更早原线需要救棋。
- 困难的有限战术延伸包含危险五连与相关攻防点，仍最多额外两条命令，受绝对深度、节点、时间和取消限制。
- 所有根着法都得到绝对必败分时，以五连攻防优先级打破平局；其余 Alpha-Beta 边界值不作为精确同分替换。

规则核心、会话权限、两条命令悔棋、有限自动重试、存档格式和恢复后的等待行为均未修改。

## 验证

新增专项覆盖固定五子护线竞速、同色换线继承、必败时施压、相关提子识别、三气远程候选保留、完整合法拆线、一气救棋时机、黑白与 A/B、预算和取消。完整产品矩阵仍为 448 种规则 × 2 种 AI 身份 × 3 档难度，使用虚拟线程端口与受限真实搜索，不是完整实战胜率研究。

复现命令：`npm run build:ai`、`npm run build`、`npm run check`、`node --test --test-reporter=tap tests/*.test.mjs`。最终检查计数与交付记录见 `reports/ai-p5-9-verification.json`。本轮不沿用旧版对战胜率作新版评级，也不改变胜负规则来回避拆线。
