# AI 基础战术 · P5.2

本阶段加入可以实际推荐动作的本地基础 AI。规则仍为 `2.1.0-r3`，原有规则和会话内核未修改。当前可玩界面继续为双人模式；人机界面、Worker、严格时间／节点预算及两档棋力差异按后续阶段接入。

## 现在会做什么

| 能力 | 实现方式 |
| --- | --- |
| 合法选点 | 完整保留规则引擎给出的所有落点，包含全盘远点；正常行棋还保留停手 |
| 获胜与紧急防守 | 每个候选都由核心模拟；已确认获胜优先，避免已验证的对方下一手获胜 |
| 提子与救棋 | 全盘检查棋块及气；识别直接补气、别处提子救棋和新产生的自紧气 |
| 五连确认 | 保留每个候选的原有时钟；检查破线、较早候选、换线继承及派生自动停手 |
| 进攻和防守四连 | 几何扫描生成提示，再通过核心实际模拟对方的成线应手；按开局方向设置工作 |
| 摆局与选色 | A 连续摆三子；第一子靠中心，第二子保持紧凑的两格间距，第三子减小静态执色优势；B 比较两种执色 |
| 停手 | 可用停手确认已有胜势；所有落子都会让对方立即获胜时，可以停手取得合法和棋 |

摆局均衡只是启发式，不能代替分配置的胜率研究。简单和标准暂用同一组基本优先级，种子只参与同分动作选择。

## 裁决和排序

候选的合法性、提子、禁重复、五连计时、自动停手和最终胜负全部来自 `core.applyAction`。AI 中的几何评分只用于排序，不另外定义胜负。

优先比较实际终局与已发现的危险：已获胜；尚未发现所扫描应手能立即获胜的非终局；和棋；存在已验证的对方下一手获胜；已经落败。同类候选再比较较早五连、破线、救棋、提子、连线潜力和自紧气。已经获胜时优先用停手结束，无须额外落子。

对方应手扫描包括：所有几何四连补点；存在候选时的全盘提子点；存在候选时的停手。每个应手仍要经过规则引擎，所以违法劫争、自杀或按另一方向才成立的连线不能被直接宣称为胜棋。当前不会穷举所有普通应手或搜索多手杀法；“未发现立即落败”不等于已经证明安全。

本阶段不裁掉根候选。获胜、成线、破线、提子、救棋、封四，以及存在已知败着时保留下来的安全替代动作，会标记为 `critical`，供 P5.3 做普通候选缩减时保留。

## 两个重点复杂局面

远处提子破线：测试构造了由正交连接形成的黑色阶梯棋块，其中 A1—E5 已构成对角五连。白方在 F8 填掉整块的最后一气，一次提掉 12 子并解除五连。F8 距五连最近点也有三格，不会依赖只看五连附近的候选规则。固定五子和同色换线继承两种模式均验证。该测试为构造布局使用 12 手延迟，不改变产品默认四手。

不同候选时钟：黑色六连的两个固定五子分别在第 9、11 手形成，12 手延迟下在第 21、23 手确认。白方第 20 手若提掉旧五连的端点，固定五子模式保留第 23 手的新候选；同色换线继承模式仍沿用第 21 手的旧时钟。AI 直接使用核心模拟出的两个结果，避免把“提掉一端”一概当成已解围。

## 接口

```js
import { listAIActions, analyzeTactics, pickBasicAction,
  recommendBasicAction } from './dist/ai/src/index.js';

// match 必须由核心创建或由 prepareSearch 完整重放。
const result = recommendBasicAction(match, seed);
if (result.ok) {
  const { action, analysis } = result.value;
  // action 交给主线程 AITurn.accept 的正式结果路径；不直接修改当前棋局。
}
```

| 接口 | 输出 |
| --- | --- |
| listAIActions(match) | 全部合法 AI 操作；排除认输与伪造共同同意 |
| analyzeTactics(match) | 排好序的全部候选、各自核心分支、战术信号和已验证的危险应手 |
| pickBasicAction(analysis, seed) | 从最高优先级的同分候选中按种子选一手 |
| recommendBasicAction(match, seed) | 完成分析并返回动作与分析结果 |

每个候选含 `action, next, tier, score, critical, reasons, signals`。`next` 是核心创建的不可变分支，不修改输入 Match。分析中的 `simulatedActions` 统计核心模拟尝试次数，包含被拒绝的应手，不冒充协议中的搜索节点数。

这些同步接口是搜索基础；不能在当前网页点击回调里直接运行。P5.3 将接入可中断的预算控制、真实统计和更深搜索，P5.4 将在 Worker 中运行。本阶段没有把计算预算“校验通过”描述成预算已被严格执行。

## 验证范围

新增 1,792 个实际选点组合：448 种规则 × A／B 两个真实玩家身份 × 简单／标准两档设置，覆盖三手摆局、选色后的连续操作、正常行棋、完整候选和任务提交。它不表示已经分别验证两档棋力。

另有 26 项战术与集成测试，包含获胜、防守单端四、双端四仍有危险、延迟确认、远处提子、直接救棋、提子救棋、自紧气、PSK、方向、长连、独立计时与换线继承、停手确认胜利／取得和棋、自动停手、不可变性，以及无界面双 AI 冒烟。冒烟每局最多运行 60 条显式命令，只用于检查流程；正式人机入口仍禁止双 AI。

P5.1 的 1,843 项接口与网页／会话回归也再次验证。构建和检查命令见主框架，完整阶段记录见 `reports/ai-p5-2-verification.json`。
