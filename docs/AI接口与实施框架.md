## 模块与数据流

新增 `packages/ai/src`，编译入口 `dist/ai/src/index.js`。规则裁决仍由 `core` 负责，实时权限和提交仍由 `session` 负责。

1. 主线程调用 `beginAITurn(session, {budget?})`，创建 `AITurn`。只接受非竞技的一人一 AI 练习局，且当前应由 AI 操作。
2. 每条 AI 显式命令创建独立模块 Worker，等严格的 ready 握手后只发送 `turn.request`。`AITurn` 私下保留 Session 原始任务令牌，副本没有提交权限。
3. Worker 调用 `runSearch(raw)`，从进入函数开始计时，逐条验证与重放完整棋谱，再执行搜索。`prepareSearch` 继续保留为不带预算的读取工具。
4. 主线程把结果交给 `turn.accept(raw)`。先核对关联字段，再由 Session 和规则引擎重验动作；通过后原子提交一条命令及派生自动停手。
5. 没有可信结果时调用 `turn.stop(...)`，暂停并清除任务。P5.4 调度器清理监听器和定时器并调用 `Worker.terminate()`；底层失败后等待明确重试。P5.5 产品层对指定可恢复错误最多自动调用两次重试，每次仍创建新 Worker 和任务，不复用旧结果。

`AITurn` 是提交适配器；`AIWorkerController` 负责后台调度和生命周期，详见 [后台任务 P5.4](AI后台任务P5.4.md)。P5.5 页面仅在人机练习局创建宿主；恢复棋局后先保持等待，用户明确继续才开放操作或启动新任务。新建、读档和页面离开时关闭旧宿主，存储冲突时暂停宿主并锁定操作，避免旧任务写入新棋局。

`packages/ui/ai-recovery.mjs` 的 `createRecoveringAI` 在原调度器外添加有限恢复策略。产品默认启动等待 5,000 ms、搜索消息宽限 1,000 ms，不改变搜索预算；`AI_NO_RESULT`、`AI_WORKER_FAILED`、`INVALID_AI_REPLY` 在同一棋局对象、同一 matchId 且仍轮到 AI 时，按 250／750 ms 延迟最多自动重试两次。期间显示 `retrying`，次数耗尽后保留 `failed`。取消、非法棋步、用户暂停、终局、换局或销毁不自动继续。后台任务文档中的 3,000／250 ms 仍是 P5.4 底层默认值。

P5.6 为浏览器适配器增加提交前的存储守卫：ready、reply、error 和 messageerror 在交给底层调度器前检查存档是否仍由当前页面持有；即使未收到跨标签页事件，冲突也先暂停，不让过期回复改变内存棋局。此守卫不改变 P5.4 的任务令牌或结果合法性裁决。

## 协议 v1

协议版本独立于规则版本和存档版本。未识别版本、额外字段和损坏数据都会被拒绝。

| 请求字段 | 约定 |
| --- | --- |
| protocolVersion／kind | `1`／`search` |
| context | `requestId, matchId, revision, taskId, actor`；actor 为 A 或 B |
| record | 完整 `MatchRecord`，含规则和全部显式命令；不能只传最终棋盘 |
| level／seed | `easy` 或 `standard`；无符号 32 位整数种子 |
| budget | `timeMs, maxNodes, maxDepth`，均为有界正整数 |

每次创建任务获得新的 requestId。同一主线程运行期内，新建或恢复的 Session 即使误用相同 matchId 和 revision，旧结果也不能对应新任务。P5.5 页面宿主销毁时调用调度器 `close()`；恢复时创建新宿主，并在用户明确继续后创建新任务。

| 难度 | 时间预算 | 节点预算 | 最大深度 |
| --- | ---: | ---: | ---: |
| 简单 | 300 ms | 2,500 | 2 |
| 标准 | 1,200 ms | 15,000 | 6 |
| 调试覆盖上限 | 10,000 ms | 1,000,000 | 12 |

这些是工程预算，不是棋力评级。深度表示显式命令层数；自动停手跟随该命令，不额外占层。节点统计为根节点加分支与战术模拟的探测次数：非法探测和命中请求内缓存的重复探测均占一个额度；重放不占节点额度，但计入时间。标准最大深度在 P5.7 从 4 调为 6，时间与节点不变。节点和深度有硬限制；单调时钟在检查点停止搜索，单次不可分割规则运算可能略过时间预算。Worker 继续实际终止过期或被取消的任务。

结果公共字段为 `protocolVersion:1, kind:"result", context, status, stats`。stats 含非负有限数 `elapsedMs`、不超过请求上限的整数 `nodes`、`completedDepth`；深度为 0 允许返回尚未完成首层搜索时保留的合法候选。统计值只用于诊断，不是任务权限或可信计时来源。

| status | 附加字段 | 主线程处理 |
| --- | --- | --- |
| move | action | 重验后提交 |
| timeout | action | 使用预算耗尽时保留的最佳合法候选，重验后提交 |
| cancelled | 无动作字段 | 暂停，等待继续或重试 |
| failed | reason 为 `no-action`／`internal` | 暂停，等待重试 |

AI action 仅允许 `place`、`choose-color`、`pass`。禁止 AI 搜索结果认输、伪造共同同意或代替另一玩家操作。timeout 缺少候选属于无效结果；计算崩溃和无结果超时都不能自动变成停手或认输。最终一次不可分割规则计算可能略过时间预算；只要任务仍有效，可接受附有合法候选的 timeout。宿主硬超时已经取消的任务，随后到达的结果一律失效。

关联字段完整但属于旧任务的结果直接忽略，不暂停新任务。当前任务的格式错误、非法建议、崩溃、取消或无结果会暂停；棋盘、完整棋谱和手数保持不变。再次继续须新建任务。成功提交后重复结果也无效。

## 必须维持的规则语义

- 三手摆局由 A 连续操作，B 选白后可能紧接着再由 B 落白子。搜索的最大化／最小化方应按真实玩家计算，不能简单按层或颜色交替。
- 从完整命令记录恢复所有 PSK 历史、执色映射、当前阶段、候选及各自的形成／到期手数。局面缓存也必须考虑这些信息；仅以棋盘为键会误判合法性和胜负。
- 搜索、读取和取消任务不增加对局手数。只有提交成功的落子／停手与规则派生自动停手推进确认计时。
- 内核每次提交和悔棋的单位仍是一条显式命令及全部派生自动停手。P5.5 界面将一次悔棋封装为同步撤回最后两条命令，不足两条时只撤回一条；双人整次撤回须对方同意，练习不要求 AI 同意。整个封装完成后才同步宿主；退回 AI 回合时暂停，等待手动继续，退回人类回合则允许玩家操作。
- 终局优先；紧迫五连确认及破线、棋块安全和提子随后；一般连线潜力再后。搜索剪枝必须保留立即获胜、防守、提子和救棋候选，特别是远处收气提掉组成五连的整块棋。

## 存档兼容

P5.8 新增困难档 `hard`，详见 [困难 AI](困难AIP5.8.md)。仅扩展控制者难度枚举与验证器，保持 v1 存档和原任务权限；困难存档需要支持该枚举的新版本。P2 历史哈希保持原样，会话的两处扩展由独立构建与 SHA-256 清单核验。

继续使用已有 `SessionSave` v1，不增加控制者字段。AI 设置保存为 `{kind:"ai",level,seed}`，绑定 A 或 B；规则和已走命令以棋谱为准。

`restorePlayableSession(newMatchId, raw)` 接受 SessionSave v1、其 JSON 文本或当前规则版本的原始 MatchRecord。纯棋谱默认恢复为双人局；单 AI 的非竞技会话恢复为练习局；双 AI 或竞技 AI 会话在第一版入口拒绝。网页外壳中的玩家姓名等元数据继续交由 UI 适配器处理。

网页继续使用 `webSchemaVersion:1` 外壳，携带玩家姓名、A/B 映射、局数与 SessionSave v1，不另增存档版本。人机练习导入与自动恢复均保留难度、AI 身份和种子；姓名仍映射至固定 A/B。覆盖进行中的练习需确认；活跃双人局继续遵守取消开局、认输及双方同意的既有锁定。

存档不包含有效任务、结果、暂停状态、同意请求、提示授权或计时器；恢复完整重放后，宿主先保持 AI 等待，用户明确继续才创建新任务。种子用于未来候选排序中的可复现随机选择；不同算法版本、预算或实际超时时机不保证产生完全相同的 AI 决策，已走棋谱始终是历史依据。

## 构建与验证

正常网页构建使用已提交的编译结果，无运行时依赖。修改 AI TypeScript 后：

```sh
npm install --prefix tools/ai
npm run build:ai
npm run build
npm run check
npm run test:ai
node --test tests/session.test.mjs tests/restore-session.test.mjs tests/web.test.mjs
```

如已有 TypeScript 7.0.2，可用环境变量 `QILINE_TYPESCRIPT_ROOT` 指向其包根目录。AI 构建只替换 `compiled/ai`，不覆盖冻结的 P2 规则与会话产物；源码、编译结果及网页副本通过 SHA-256 清单检查一致性。

P5.1 历史结果见 `reports/ai-p5-1-verification.json`，其矩阵使用预先指定的测试动作。P5.2 结果见 `reports/ai-p5-2-verification.json`；新增矩阵实际调用基础选点并走完整提交路径。二者都不证明胜率公平或高水平棋力。

P5.3 的预算矩阵、搜索专项与本轮回归结果见 `reports/ai-p5-3-verification.json`。`npm run test:search` 单独执行搜索验收；正常构建流程仍为 `build:ai`、`build`、`check`。

P5.4 的线程、超时、竞态、实际浏览器及回归结果见 `reports/ai-p5-4-verification.json`。`npm run test:worker` 运行本阶段 1,824 项自动检查；浏览器开发验收页与产品页面分开构建，参见后台任务文档。
