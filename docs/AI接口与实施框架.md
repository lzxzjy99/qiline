# AI 接口与实施框架

阶段：P5.1，2026-10-20。规则保持 `2.1.0-r3`。本阶段交付可运行的接口、任务边界和存档适配测试；还没有搜索算法、后台 Worker、人机界面或新的 Windows 包。

第一版采用本地搜索，支持一人对一台 AI、简单／标准两档。控制者绑定 A/B；可让人或 AI 摆局，换色不交换真实玩家身份。暂不加入训练模型、联网服务或自动认输。

## 模块与数据流

新增 `packages/ai/src`，编译入口 `dist/ai/src/index.js`。规则裁决仍由 `core` 负责，实时权限和提交仍由 `session` 负责。

1. 主线程调用 `beginAITurn(session, {budget?})`，创建 `AITurn`。只接受非竞技的一人一 AI 练习局，且当前应由 AI 操作。
2. 仅把 `turn.request` 的副本发送给未来的 Worker。`AITurn` 私下保留 Session 原始任务令牌，副本没有提交权限。
3. Worker 入口调用 `prepareSearch(raw)`，严格校验并从完整棋谱重放；未来在返回的 Match 上搜索。
4. 主线程把结果交给 `turn.accept(raw)`。先核对关联字段，再由 Session 和规则引擎重验动作；通过后原子提交一条命令及派生自动停手。
5. 没有可信结果时调用 `turn.stop(...)`，暂停并清除任务。P5.4 再接入真实的 Worker 终止与计时器。

`AITurn` 是提交适配器，不负责自动调度下一回合。当前网页版继续拒绝人机存档，待 P5.5 接入完整人机入口后再开放。

## 协议 v1

协议版本独立于规则版本和存档版本。未识别版本、额外字段和损坏数据都会被拒绝。

| 请求字段 | 约定 |
| --- | --- |
| protocolVersion／kind | `1`／`search` |
| context | `requestId, matchId, revision, taskId, actor`；actor 为 A 或 B |
| record | 完整 `MatchRecord`，含规则和全部显式命令；不能只传最终棋盘 |
| level／seed | `easy` 或 `standard`；无符号 32 位整数种子 |
| budget | `timeMs, maxNodes, maxDepth`，均为有界正整数 |

每次创建任务获得新的 requestId。同一主线程运行期内，新建或恢复的 Session 即使误用相同 matchId 和 revision，旧结果也不能对应新任务。页面重载时 P5.4 宿主还须终止旧 Worker，重新建任务。

| 难度 | 时间预算 | 节点预算 | 最大深度 |
| --- | ---: | ---: | ---: |
| 简单 | 300 ms | 2,500 | 2 |
| 标准 | 1,200 ms | 15,000 | 4 |
| 调试覆盖上限 | 10,000 ms | 1,000,000 | 12 |

这些是初始工程预算，不是棋力测试结果。深度表示搜索中的显式命令层数；自动停手跟随该命令，不额外占层。节点定义为搜索展开的局面，根节点计入；棋谱恢复计入时间，不计入搜索节点。P5.2／P5.3 必须实际执行这些预算检查，本阶段只校验契约。宿主用单调时钟管理任务总等待时间，P5.4 接入实际计时与终止。

结果公共字段为 `protocolVersion:1, kind:"result", context, status, stats`。stats 含非负有限数 `elapsedMs`、不超过请求上限的整数 `nodes`、`completedDepth`；深度为 0 允许返回尚未完成首层搜索时保留的合法候选。统计值只用于诊断，不是任务权限或可信计时来源。

| status | 附加字段 | 主线程处理 |
| --- | --- | --- |
| move | action | 重验后提交 |
| timeout | action | 使用预算耗尽时保留的最佳合法候选，重验后提交 |
| cancelled | 无动作字段 | 暂停，等待继续或重试 |
| failed | reason 为 `no-action`／`internal` | 暂停，等待重试 |

AI action 仅允许 `place`、`choose-color`、`pass`。禁止 AI 搜索结果认输、伪造共同同意或代替另一玩家操作。timeout 缺少候选属于无效结果；计算崩溃和无结果超时都不能自动变成停手或认输。最终一次不可分割规则计算可能略过时间预算；只要任务仍有效，可接受附有合法候选的 timeout。宿主硬超时已经取消的任务，随后到达的结果一律失效。

关联字段完整但属于旧任务的结果直接忽略，不暂停新任务。当前任务的格式错误、非法建议、崩溃、取消或无结果会暂停；棋盘、完整棋谱和手数保持不变。再次继续须新建任务。成功提交后重复结果也无效。

## 必须维持的规则语义

- 三手摆局由 A 连续操作，B 选白后可能紧接着再由 B 落白子。搜索的最大化／最小化方应按真实玩家计算，不能简单按层或颜色交替。
- 从完整命令记录恢复所有 PSK 历史、执色映射、当前阶段、候选及各自的形成／到期手数。局面缓存也必须考虑这些信息；仅以棋盘为键会误判合法性和胜负。
- 搜索、读取和取消任务不增加对局手数。只有提交成功的落子／停手与规则派生自动停手推进确认计时。
- 一条显式命令及全部派生自动停手作为一次提交和悔棋单位。P5.4 调度器应在悔棋后保持等待，避免落在 AI 回合时立即重下。
- 终局优先；紧迫五连确认及破线、棋块安全和提子随后；一般连线潜力再后。搜索剪枝必须保留立即获胜、防守、提子和救棋候选，特别是远处收气提掉组成五连的整块棋。

## 存档兼容

继续使用已有 `SessionSave` v1，不增加控制者字段。AI 设置保存为 `{kind:"ai",level,seed}`，绑定 A 或 B；规则和已走命令以棋谱为准。

`restorePlayableSession(newMatchId, raw)` 接受 SessionSave v1、其 JSON 文本或当前规则版本的原始 MatchRecord。纯棋谱默认恢复为双人局；单 AI 的非竞技会话恢复为练习局；双 AI 或竞技 AI 会话在第一版入口拒绝。网页外壳中的玩家姓名等元数据继续交由 UI 适配器处理。

存档不包含有效任务、结果、暂停状态、同意请求、提示授权或计时器；恢复完整重放后，宿主显式创建新任务。种子用于未来候选排序中的可复现随机选择；不同算法版本、预算或实际超时时机不保证产生完全相同的 AI 决策，已走棋谱始终是历史依据。

## 构建与验证

正常网页构建使用已提交的编译结果，无运行时依赖。修改 AI TypeScript 后：

```sh
npm install --prefix tools/ai
npm run build:ai
npm run build
npm run check
npm run test:ai
node --test tests/session.test.mjs tests/restore-session.test.mjs tests/web.test.mjs
```

如已有 TypeScript 7.0.2，可用环境变量 `QILINE_TYPESCRIPT_ROOT` 指向其包根目录。AI 构建只替换 `compiled/ai`，不覆盖冻结的 P2 规则与会话产物；源码、编译结果及网页副本通过 SHA-256 清单检查一致性。

本轮基础矩阵与专项结果见 `reports/ai-p5-1-verification.json`。矩阵使用预先指定的测试动作，证明接口在全部配置下正确传递与提交，不证明 AI 已会下棋，也不证明胜率公平。
