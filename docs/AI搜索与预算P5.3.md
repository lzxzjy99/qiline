# AI 搜索与预算 · P5.3

本阶段实现本地、可按计算预算停止的迭代加深 Alpha-Beta 搜索。规则仍为 `2.1.0-r3`，冻结的规则和会话内核没有改动。当前网页版仍为双人模式，Worker 和人机界面按 P5.4、P5.5 接入。

## 两档策略

| 设置 | 简单 | 标准 |
| --- | ---: | ---: |
| 默认时间 | 300 ms | 1,200 ms |
| 默认节点额度 | 2,500 | 15,000 |
| 默认最大深度 | 2 条显式命令 | 4 条显式命令 |
| 深层搜索普通候选宽度 | 6 | 12 |

主线程仍可在协议规定上限内覆盖预算。候选宽度由难度决定，预算覆盖不会改变难度。两档区别已经体现在搜索过程；测试中的一个双端四局面，标准档在三条命令后确认胜利，简单档两条命令尚未见到终局。这不是标准档胜率或等级分证明。

## 搜索方式

先模拟根局面的所有原始候选，逐个通过核心验证合法性；若预算先耗尽，就只能使用目前已验证的候选。找到实际立即获胜的着法可以直接结束，其值已经达到评价上界。

随后逐层加深。深层搜索保留全部重要候选，并限制普通候选数量。重要候选包括成线、封四、全盘提子、直接补气、提子救棋、破坏确认候选、实际终局和停手。远处棋块的最后一气不会因距离五连太远被裁掉。P5.2 的完整根分析接口继续保留。

最大化／最小化依据当前真实玩家 A/B。A 连摆三子依然连续最大化；B 选白后若仍由 B 行棋，也继续按 B 的视角搜索。不会每走一层就机械换号。自动停手属于一条命令的完整核心结果，不额外占搜索深度。

评价先看核心的实际胜负；其数值严格大于所有普通估值。未终局时考虑五连的确认时间、连线潜力、棋块气数和棋子存活；选色前考虑 B 可选择较强颜色以及白先行。估值和排序都不能自行宣布获胜或违法。

不使用按最终棋盘复用价值的置换表。每个搜索分支都是核心创建的 Match，完整保留 PSK 历史、阶段、执色、全部候选和各自时钟。上一轮主变化只用于下一轮排序，不充当另一局面的合法性或胜负缓存。

## 预算的实际含义

- 进入 `runSearch` 立即取得单调时钟起点。请求校验、逐条棋谱重放和搜索均计入本次时间。
- 棋谱必须完整验证后才能产生候选。重放中断返回无着法结果；不会只用已验证的一部分历史继续下棋。
- 节点额度为根节点一次，加每次尝试调用核心进行搜索模拟的次数。非法候选检查也计入。棋谱重放不占节点额度。
- 在调用下一次核心模拟前检查额度；不会发生“额度为 2，却模拟了 3 个节点”。最大深度也按显式命令硬性限制。
- 时间检查位于命令之间、排序／估值边界及递归节点。单次核心规则计算或一次棋盘特征计算不可在内部打断，可能略过时间预算；不会因此开始后续搜索。真正的 Worker 终止和包括启动／消息传输的总等待控制留给 P5.4。
- 普通候选裁减后的完整迭代，才增加 `completedDepth`。这表示所选搜索树的完整一轮，包含 Alpha-Beta 合法剪枝，不表示穷举全盘所有多手变化。

## 中断与结果

| 情况 | 输出 |
| --- | --- |
| 完成设定深度，或找到实际立即获胜 | `move` |
| 时间／节点用尽，已有已验证着法 | `timeout`，附合法动作 |
| 第一层仍未完成 | 深度为 0，使用目前评估较好的合法候选；如果刚验证第一手即中断，可保留该已验证动作 |
| 较深一轮中断 | 保留上一轮完整结果，不用较深一轮的局部评分覆盖它 |
| 重放尚未结束，或根节点额度不足以验证一手 | `failed: no-action`，由宿主暂停等待重试 |
| 已观察到取消 | `cancelled`，不附可提交动作；即使报告结果时恰好又到达截止时间，也不重新变成可提交结果 |
| 时钟倒退、宿主故障或内部异常 | 失败，等待重试 |

无可信着法不会自动变成停手或认输。所有着法仍须主线程 `AITurn.accept` 核对任务并再次通过核心；暂停、重开或终局后到达的结果不会落到新棋局。

## 调用

```js
import { runSearch } from './dist/ai/src/index.js';

const result = runSearch(request);
if (result.ok) {
  const { reply, details } = result.value;
  // 未来 Worker 只把 reply 作为协议结果发回主线程。
  // 主线程持有原始 AITurn，调用 turn.accept(reply)。
}
```

request 是 `turn.request` 的可序列化副本。`reply` 保持协议 v1；`details` 是诊断数据，含停止原因、普通候选宽度、最大访问深度、剪枝数、估值和主变化，不是任务权限或存档。

若 `result.ok` 为 false，请求或棋谱没有通过验证，宿主应按当前任务失败处理并暂停；不能把错误转换成落子或停手。

可注入本地 `SearchHost` 的 `now()`、`isCancelled()`，用于测试或宿主的共享取消标记；函数不放入 Worker 消息。`now` 必须单调、有限且非负。搜索目前是同步函数；P5.4 会把它放入 Worker，不能直接放在棋盘点击回调里执行。

相同请求、种子和确定的节点／时间条件会重复相同选择；实际耗时受设备影响，中断时机不同可能产生不同着法。

## 验证范围

新增 1,792 个组合：448 种规则 × A/B 两种身份 × 两档难度。矩阵使用确定时钟与较小节点额度，实际验证重放、预算中断、合法结果、身份、换色后的连续操作及主线程提交。它不是 1,792 局完整对战，也不是对全部变化的穷举。

另有搜索与树算法专项：独立穷举 oracle 对照 400 组真实玩家视角的混合轮次树、剪枝、三手胜势、远处提子破线、劫争、确认时钟、同玩家连续操作、每种预算边界、上一轮结果保留、取消竞态、坏时钟、自动停手和真实单调时钟检查。当前默认档位也在 9 路和 19 路运行检查。

本轮还重跑了接口矩阵、基础战术、会话和网页模型回归。详细计数见 `reports/ai-p5-3-verification.json`。本阶段没有真实 Worker、浏览器人机界面或 Windows 运行验收，也不声称已证明 AI 棋力或规则胜率公平。
