# 困难 AI · P5.8 / v0.5.8

在人机练习中新增“困难”，与简单、标准并列。每手搜索预算为 8 秒、200,000 次规则试算、最多 12 条显式命令；通常耗时数秒，遇到可确认的直接胜着可提前返回。预算是上限，不能把深度上限理解为每步必然算满 12 手。后台独立 Worker 运行，思考期间可查气、暂停、导出；故障沿用最多两次隐式自动重试和最终失败提示。

## 搜索变化

困难档沿用 P5.7 的提子、棋块安全、跳空与双重威胁评估；保持集中的候选宽度，将增加的资源用于深入搜索。请求内的历史排序与每层两个截断优先着法改善剪枝效率。先按棋形选入安静候选，再排序，避免历史排序排除必要的棋形着法。所有识别到的关键候选仍可参与常规搜索。

即时胜负威胁或即将到期的五连候选出现在搜索边界时，最多追加两条关键攻防命令。追加搜索只考虑补五、拆五、紧气提子和救棋等相关动作，并始终遵守请求的绝对深度、节点、时间和取消限制；延迟模式下普通的“四子可补五”不会单独触发扩展。所有建议仍须由原规则内核确认合法性和终局。

简单与标准的预算和搜索策略保持原设置。困难并非穷尽搜索，不承诺不败。

## 存档兼容与边界

保持 SessionSave v1 与网页外壳 v1；控制者的 level 接受 easy / standard / hard。旧版简单、标准存档可由新版恢复；包含 hard 的新存档需要 v0.5.8 或之后版本。难度、A/B 身份、种子和完整命令记录保留，恢复后等待明确继续。选色不会交换控制者。

P2 规则核心未修改。会话仅有两处难度枚举／验证器扩展，没有调整任务权限、共同同意、悔棋或重放语义。`scripts/build-session-levels.mjs` 去掉这两处扩展后须与历史源码哈希相同，再以固定 TypeScript 7.0.2 编译会话；记录于 `reports/session-hard-level-extension.json`。历史 P2 哈希报告原样保留，`npm run check` 同时核对原基线与扩展产物。

```sh
node scripts/build-session-levels.mjs
npm run build:ai
npm run build
npm run check
```

## 验证与复现

专项覆盖困难预算、绝对深度、真实规则防守、远程提子拆五、固定资源可复现、长思考暂停、过期结果拒绝、难度选择、保存恢复和两手悔棋。三档均纳入规则／身份矩阵，其中产品组合为 448 种规则 × 2 种 AI 身份 × 3 档难度，共 2,688 项。矩阵采用虚拟线程端口与小额度真实搜索，不是 2,688 局完整实战。

`node scripts/benchmark-hard-ai.mjs` 执行选择用的 24 局，`--holdout` 使用未参与方案选择的新种子再走 24 局。每局完整重放检查；9 路、三手换色、两种方向、延迟 0／4、困难交替 A/B。标准 1,200 节点／6 层，困难 12,000 节点／12 层，搜索时钟固定为零；这是缩小额度后的确定性对照，不等同于产品实际耗时或通用胜率评级。未完成局不按评估分判胜。最终汇总见 `reports/ai-p5-8-verification.json`。

浏览器检查包括三档选择、真实困难应手、思考中暂停与查气、导出包含 hard、刷新恢复等待继续，以及 390px 窄屏卡片。窄屏模拟不替代实体手机验收。Windows 包与网页共用相同资产，实际运行范围另见随包记录；结构验证的 runtimeTested:false 不代表已完成平台验收。
