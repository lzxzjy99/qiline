# 困难 AI 进阶 · P5.10 / v0.5.10

本轮以 v0.5.9 的困难 AI 为固定对手，目标是在预先确定的独立对照中达到至少 80% 的胜局比例。简单与标准档的策略和预算不变。困难档每手最多思考 2 分钟、400 万次规则试算、16 条显式命令；思考中仍可查气、暂停和导出。

## 实现

困难档优先深入当前最好的变化，其他候选先用窄窗口试探；只有可能超过当前最好结果时才完整重算。保留已找到的好应手供下一轮排序，同一局面对象的重复评分在请求内复用。不会把只有棋盘相同、PSK 历史或五连时钟不同的状态合并。

应手提示按完整命令路径记录并限制数量，每轮加深开始时固定提示快照。首选安静着法占用原有候选名额；学习到的历史排序只改变顺序，不能改变试探和完整重算使用的候选集合。即使规则转换缓存已满、重算产生了新局面对象，这一约束仍成立。

增加五连存活的充分判断：计算确认前对方最多还能落几手；若五连涉及的每个完整棋块，其气数都严格超过这个手数，且不存在更早或同到期的敌方五连时钟，则己方持续停一手即可保证这条五连存活。气数恰好相等不能判为安全。困难档据此提前阻挡对手下一手就能形成的安全五连，避免直到倒计时结束才发现已无法拆线。该判断只结束搜索中的已解分支，分值低于真实终局；棋盘、倒计时和最终胜负仍由规则内核推进。

窄窗口重搜可复用本轮相同命令路径、相同剩余深度的精确值或上下界。缓存每轮清空并限制为 16,384 条，不跨规则历史、倒计时、候选集合或搜索轮次复用。取消和预算检查在读取缓存前执行。已证明的延迟败局与真实败局在落子选择中均视为必败，仍优先对五连施压；同色换线继承时保留有效的换线选择。

困难档在内部搜索中为对手保留最多 12 个普通应手候选，不随深度缩减到 4 个；己方深层仍逐渐收窄。根层继续检查最多 24 个普通候选，并始终保留关键攻防点。三手摆局的第三子会先检查全盘合法落点，再根据已完成评分缩小后续搜索，避免仅因离中心较远而遗漏均衡摆局。五连存活判断也用于搜索内部的应手筛选；所有候选都被证明失利时，按固定静态次序保留有用抵抗，不让动态排序改变重搜的候选集合。

另有最多 2,048 项的请求内棋形特征池，仅在困难搜索使用。相同棋盘可以复用纯几何连线与棋块特征；不同方向规则使用不同键。评分、合法性、重复历史和确认时钟始终属于各自的完整局面，不能在该池中合并。未来已证实的胜负分支在搜索内使用统一参考值，直接由规则内核确认的根层立即获胜仍优先处理。

实际胜负和合法性始终由原规则内核判定。关键提子、救棋、五连拆线、护线和确认候选继续保留；战术延伸最多额外两条命令，仍受绝对深度、节点、时间和取消约束。未完成的深层迭代会退回已完成的合法选择。三手摆局、B 选白后连续行棋等情况按真实 A/B 控制者推演，不按手数简单翻转分数。

测试过更大缓存、更多战术延伸、窄候选和静态先手加分；这些变体未进入最终方案。记录于 `reports/ai-p5-10-selection.json`。最终方案与所选调优记录逐字节核对后冻结，再进行独立对照。

## 对照口径

计划固定在 `benchmarks/generation-plan.json`：40 局、5 个未参与调优的种子、9／13 路、对角线／四方向、延迟 0／4、固定五子／同色换线继承、每组交换 A/B。每局最多 160 条显式命令，记录完整棋谱，并由规则内核重新播放核验终局。

胜率为“新版实际获胜局数 ÷ 全部 40 局”。和棋和未完成局均不算胜局，不能剔除后重新计算。正式验收使用实际单调时钟和未缩减的产品预算：旧版保持 8 秒、20 万次试算、12 层；新版为 2 分钟、400 万次试算、16 层。双方均调用各自完整的困难搜索，不将旧版改为标准档。结果反映双方不同的产品思考额度，不是等算力比较。

报告保留并发对局数量、候选文件哈希、前代 Git 提交和编译产物哈希、每手统计、每局完整记录。正式结果见 `reports/ai-p5-10-generation-holdout.json`，只有报告中 `summary.accepted:true` 且代码哈希与发布版本一致时才视为达到目标。调优用的缩小额度对照不能代替正式验收。

若正式验收失败，保留该次报告，不通过删除败局、改种子或调低旧版额度得到通过结果。继续修改算法须使用新的独立测试计划，并保留所有失败记录。

第一轮因代码复核发现试探／完整重算的候选集合可能变化而中止。当时已完成 2 局，为 1 胜 1 负，其余 38 局未完成；不计为正式通过结果。原计划、完整终局记录和中止原因分别保留在 `benchmarks/generation-plan-attempt-1.json` 与 `reports/ai-p5-10-generation-attempt-1-aborted.json`。修复属于搜索一致性约束，未根据该轮对局记录调优；修复后重新固定未见种子进行最终验收。

第二轮完成 22 局，为 13 胜、9 负。其余 18 局即使全部获胜也最多 31／40，已不可能达到目标，因此按仅用于拒绝的提前停止规则中止；记录完整保留在 `reports/ai-p5-10-generation-attempt-2-rejected.json`，原计划保留在 `benchmarks/generation-plan-attempt-2.json`。没有将该轮当作通过结果，也未使用其棋谱调优。后续算法依据独立的规则证明与小棋树穷举验证升级；调优仍使用原训练种子，新正式验收须另固定未见种子。

## 验证与复现

`npm run build:ai`、`npm run build`、`npm run check` 编译并核对原规则核心、会话扩展与 AI 哈希。自动测试涵盖 PVS 与独立穷尽极小极大值的一致性、分数边界重搜、同一玩家连续行动、预算、取消、真实 Worker、五连攻防、存档恢复、两条命令悔棋及有限重试。

在完整 Git 历史的源码目录执行 `npm run benchmark:generation` 可复现正式口径。`scripts/prepare-ai-predecessor.mjs` 从固定提交 `bf1fb00355295ae6b8d1cb8fd200c17148508e83` 提取原编译产物，不依赖已发布网站或可变分支。正式对局较耗时；`--scaled` 仅供本地调优，不能使正式验收通过。

这是有限、明确条件下的版本对照，不是所有规则配置和所有设备上的通用胜率承诺。核心规则与会话权限、存档格式、两手悔棋、自动重试上限保持原约定。原生窗口和其他设备上的手工验收范围另见随包记录。
